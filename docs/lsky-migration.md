# 从蓝空图床（Lsky Pro）迁移

在后台「站点管理 → 站点设置 → 备份/导出」页底部的「蓝空迁移」上传蓝空数据库导出的 `.sql` 文件，就能把组、用户、Token、相册和图片导入 ImgNest。每张图都**按原路径走一遍 ImgNest 的上传流水线**：格式探测、EXIF 入库、WebP、本地 + 云端缩略图、响应式衍生图（规则开启时）和配额，和新上传的图片一样。

图片有两种导入方式：

| | 原地接管（推荐） | 下载后重新保存 |
| --- | --- | --- |
| 原图 | 留在蓝空原来的 S3 桶里，**一个字节都不改** | 从旧链接下载，写进规则的存储（一般是新桶） |
| 旧链接 | 不用切换，照常可用 | 导入后把旧域名切到新桶 |
| 新增的文件 | WebP、缩略图、响应式图，放在原图旁边 | 原图、WebP、缩略图、响应式图 |
| 原图里的 GPS 等 EXIF | 保留在桶里的文件中（ImgNest 公开接口不返回） | 按规则无损抹除，`md5` 会和蓝空记录不同 |
| 要求 | 规则的存储就是旧桶，且桶开启了版本控制（B2 默认开启） | 运行 ImgNest 的机器能访问旧链接 |

## 会导入什么

| 蓝空 | ImgNest | 说明 |
| --- | --- | --- |
| `groups` | `groups` | 同名组直接复用（不改限额）；新建的组带上 `maximum_file_size`、`limit_per_minute`、可用格式（ico/psd 等 ImgNest 不支持的会去掉），默认规则设为导入时选的规则 |
| `users` | `users` | 同邮箱账号直接复用（不改密码/角色/组）；新账号保留 bcrypt 密码（`$2y$` 可直接校验）、管理员身份、注册 IP、创建时间。用户名少于 3 个字时改用邮箱前缀，原名放进显示名 |
| `personal_access_tokens` | `tokens` | 摘要原样保留；编号没被占用时沿用原编号，PicGo/Typora 里的 `id\|secret` Token 无需更换 |
| `albums` | `albums` | 同用户同名相册复用 |
| `images` | `images` + 对象 | 路径（`pathname`）与扩展名不变，`created_at` 保留（年份为 1 的坏时间从 `uniqid` 文件名还原）；公开/私有、上传 IP、原文件名保留 |
| `configs`、`strategies` 的密钥 | 不导入 | 只读策略的公开 `url`；存储密钥、SMTP 密码在解析时直接丢弃，不保存也不显示 |

不会导入：游客上传、已停用用户的图片、ImgNest 不支持的格式（`.ico`、`.psd`），以及「保存后扩展名会变」的图片（`.jpeg`、大写扩展名，以及下载重新保存时实际格式和扩展名不符的图片），因为它们的旧链接会失效。蓝空开了「转换为 WebP」却只改了扩展名的 PNG/JPEG 照常导入：原地接管时原样保留（链接不变，不再另生成 WebP），下载重新保存时存成真正的 WebP。导入按所属用户组的单文件上限检查，不受 `server.max_upload_mb` 限制；组设为不限时最大 100 MiB。超过 20 MiB 的图片只能原地接管（下载重新保存需要先脱敏 EXIF，脱敏只支持 20 MiB 以内）。导入结束后页面会逐条列出这些图片，它们仍在旧存储里（原地接管时旧链接照常可用）。

> **管理员账号怎么对上**：账号按邮箱匹配。初始化 ImgNest 管理员时用和蓝空管理员相同的邮箱，导入后蓝空账号的图片和 Token 会直接归到这个账号下，继续用 ImgNest 的密码登录；邮箱不同则会另建一个保留蓝空密码的管理员账号。

## 网页导入步骤

1. **导出蓝空数据库**：在蓝空的 PostgreSQL 上用 `pg_dump`（纯 SQL 格式）或 DBX、Navicat 把整个库导出成 `.sql` 文件。导出里有密码哈希和存储密钥，用完删掉，不要发给别人。
2. **准备存储和规则**：
   - 原地接管：在「存储管理」里添加蓝空原来的 S3 桶（B2 的 Endpoint 填 `https://s3.<区域>.backblazeb2.com`，打开 Path Style），**Base URL 填蓝空策略里的那个地址**（例如 `https://img.example.com/ShellBlogImg`），旧链接才能和 ImgNest 的链接对上。如果文件在桶里的某个文件夹下（例如桶里的 Key 是 `ShellBlogImg/1/2025/...`），把「路径前缀」填成这个文件夹。不确定的话先留空，开始导入时 ImgNest 会先抽查几张图，找不到时会告诉你该填什么。
   - 下载后重新保存：添加一个新桶。WebP 模式不能选「仅 WebP」，否则原图链接会丢。
   - 再给这个存储建一条规则，打开缩略图和「响应式衍生图」。
3. **上传导出文件**：打开「站点管理 → 站点设置 → 备份/导出」页底部的「蓝空迁移」，确认时区（默认 `Asia/Shanghai`）后选择 `.sql` 文件。文件只在服务器内存里解析，不写入磁盘；页面会显示有多少用户、图片和存储策略。
4. **选择导入方式和规则**：原地接管时「蓝空存储策略」只选存放在这个桶里的那一个（Base URL 一致时会自动选中），其他策略的图片会因为桶里没有而失败。
5. **开始导入**：进度每两秒刷新一次，可以随时停止。导入完会列出失败和跳过的图片；修好原因后再点一次「开始导入」，已导入的会跳过，只重试剩下的。服务重启后需要重新上传一次导出文件。

> **原地接管之后**：图片由 ImgNest 管理：在 ImgNest 里删除会让旧链接立即 404（原图作为历史版本留在桶里，从回收站恢复时会写回原处），回收站到期或彻底删除时会连同原图一起删除。不要在接管后再开蓝空往同一个桶里写。

反向代理（如 1Panel 的 OpenResty）的上传大小上限要大于导出文件，Nginx 是 `client_max_body_size`；ImgNest 自己最大接收 128 MiB 的导出文件。

## 用命令行导入

不想用网页时，`imgnest import-lsky` 做的是同一件事：

```bash
# 直接读导出文件（也可以把导出加载进 PostgreSQL，再用 IMGNEST_LSKY_DSN 指向它）
docker compose run --rm -v "$PWD/LsyPro.sql:/tmp/LsyPro.sql:ro" imgnest import-lsky --dump /tmp/LsyPro.sql --dry-run
# 原地接管：规则的存储就是旧桶
docker compose run --rm -v "$PWD/LsyPro.sql:/tmp/LsyPro.sql:ro" imgnest import-lsky --dump /tmp/LsyPro.sql --policy-id 1 --adopt --limit 5
# 抽查这 5 张没问题后去掉 --limit 跑完整
```

下载后重新保存时去掉 `--adopt`，原图默认从各存储策略的 `url` 下载，也可以用 `--source-url` 换一个地址，或者先把旧桶同步到本地目录再用 `--source-dir`。命令行导入期间先停掉服务（`docker compose stop imgnest`），跑完再启动。

### 下载后重新保存：切换旧链接

1. 导入期间博客仍然读旧桶，什么都不会坏。
2. 导入并抽查完成后，把 CDN / 反代上旧链接的来源（例如 `img.example.com/old-bucket` → 新桶）切过去，再把 ImgNest 里这个存储的 Base URL 改成旧域名，旧链接就由 ImgNest 管理的对象提供。
3. 跳过的 `.ico` 等文件，切换前用 rclone 之类的工具从旧桶原样复制到新桶，旧链接照样能打开（它们不在 ImgNest 的图片列表里）。

## 之后

- 密码不是 bcrypt 的账号会导入为不可登录，用 `imgnest reset-password --email ...` 重设。
- Token 编号被占用时会换新编号，报告会写明把客户端里 `旧编号|` 改成 `新编号|` 即可。
- 以后再给别的规则打开「响应式衍生图」时，历史图片仍用后台的「响应式图片补生成」补齐；导入时规则已开启的话不需要再回填。
- 目前只支持 PostgreSQL 版蓝空的导出；MySQL 版可以先用 pgloader 之类的工具转成 PostgreSQL 再导出。
- 迁移完成后建议在 Backblaze 后台更换旧的应用密钥，并修改蓝空配置里用过的 SMTP 密码。
