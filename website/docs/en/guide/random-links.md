# Random image links

One fixed URL redirects (`307`) each visit to a random image in an album. Use it for a blog background, README image or random wallpaper.

## Where to open it

**Sign in → My albums → click an album cover or name → Random image link in the detail page header.**

My albums is at `/albums` on your site. The button is inside the album, not in the album card’s Edit dialog. On a phone, open navigation first; the detail header button may wrap onto another line.

## Create and copy a link

1. Open My albums and click the cover or name of the album to share.
2. Click Random image link in the page header to open its dialog.
3. On first use, click Enable random link. Read the private-image warning, then click Enable to confirm.
4. The dialog shows the URL field and Enabled status. Click Copy link, or select and copy the field manually if clipboard access fails.
5. Paste the URL into a signed-out browser window and check that it displays an album image before publishing it.

::: warning Private album images participate too
Enabling a random link authorizes sharing the whole album. Neither a public album flag nor the public gallery is required. Every usable album image can be selected, including private images; recycled images are excluded.
:::

### No album or no images yet

In My albums, click New album, enter a name and click Create. Select that album while uploading, or select existing images in My images and use Move to album. See [Creating an album and adding images](./albums-and-gallery.md#create-an-album-and-add-images). An empty album can have a link, but visiting it returns 404.

## Use it in a blog or README

The server generates the complete URL; do not invent the `uid` or `token`:

```text
https://img.example.com/random/{uid}/{token}
```

Replace the entire example URL below with the one you copied:

```markdown
![Random image](https://img.example.com/random/YOUR_PUBLIC_ID/YOUR_LINK_TOKEN)
```

```html
<img src="https://img.example.com/random/YOUR_PUBLIC_ID/YOUR_LINK_TOKEN" alt="Random image" />
```

WebP is preferred by default. Append `?format=original` to prefer the original. Browsers and blog platforms may cache the displayed image, and a random selection can repeat, so refreshing an article does not guarantee a different image.

## Disable, reset or delete

Open the same album’s Random image link dialog again:

| Goal | Action | Existing URL |
| --- | --- | --- |
| Pause and resume later | Turn the enabled switch off, then on when needed | Returns 404 while disabled; the same URL works after re-enabling |
| Replace the address | Click Reset link and confirm | Old URL stops working immediately; copy the new URL and update published references |
| Remove the sharing entry | Click Delete link and confirm | URL stops working immediately; enabling later creates a new URL |

These actions control the random URL. Direct image URLs already obtained by visitors remain usable. To invalidate an image at its origin, delete the image; see [Privacy and recycle bin](./privacy-and-trash.md#image-visibility-and-direct-links).

## Troubleshooting

- **Dialog cannot load the link:** click Retry and wait for a successful load before making changes.
- **404:** check that the album has an active image, the link is Enabled, the owner is enabled, and you copied the latest complete URL. Public responses intentionally do not distinguish these causes.
- **400:** remove unsupported format parameters; only `format=original` is accepted.
- **429:** wait before retrying; the limit is 600 requests per client address per minute.
- **Redirect works but the image fails:** check the storage access URL and object. The random endpoint selects and redirects; it does not proxy image files.

## Address and cache details

- `uid` is the owner’s 10-character random public ID; `token` is a 24-character random string. Both are generated by the server. Anyone holding the link can use it anonymously.
- Default selection prefers WebP and falls back to the original. `?format=original` reverses that preference.
- Redirect responses use `Cache-Control: no-store` and contain no image metadata or EXIF. File scrubbing depends on the upload policy.
- Candidates are cached for 60 seconds, up to 5000 per album with sampling beyond that. Album changes invalidate the cache; other instances without shared caching may lag up to 60 seconds. Deleted images already return 404 at their origin.
- The destination uses the storage’s `base_url`. Changing it changes direct-image destinations; the album random URL stays the same.
