# 登录保护

这一页讲三件互相配合的事:Cloudflare Turnstile 人机验证、SMTP 与邮箱验证码、找回密码。

## 从哪里设置

管理员登录 →「站点管理 → 站点设置」，按下面的页面分别保存：

| 要配置什么 | 页面与操作 | 如何确认生效 |
| --- | --- | --- |
| 开放注册 | 注册与登录（`/admin/settings/auth`）→ 选择默认用户组、打开「开放注册」→ 保存设置 | 未登录打开 `/register`，确认显示注册表单 |
| Turnstile | 同页下方「人机验证」卡片 → 填 Key、启用、完成一次验证 → 该卡片的「保存」 | 看到「人机验证已启用」后，用未登录窗口检查登录页 |
| SMTP | 邮件（`/admin/settings/mail`）→ 填配置并打开「启用邮件发送」→ 保存邮件设置 → 发送测试邮件 | 测试收件箱实际收到邮件 |
| 注册邮箱验证 | SMTP 可用后，回到「注册与登录」打开「注册邮箱验证」→ 保存设置 | 注册页出现发送验证码与验证码输入框 |

站点设置表单、验证码卡片和邮件表单各自保存；改完一个表单不会自动保存其他表单。

## 人机验证(Turnstile)

默认关闭。开启后保护网页登录、注册和发送验证码:

- 在后台「系统设置 → 注册与登录」一步配置:填 Site Key 和 Secret(Secret 留空则沿用已保存的),勾选启用,在页面上完成一次真实验证,服务端核验通过立即生效;关闭不需要验证。允许的域名默认取当前访问域名,在高级选项里调整。
- 只支持 Turnstile;域名必须是精确的小写完整域名,最多 10 个,不支持通配符、端口和 IP。
- Secret 只写不读,用 `security.master_key` 加密保存——**更换主密钥前先备份**,否则已保存的 Secret 无法解密(见[配置](./configuration.md))。
- 旧的三步式 draft / test / activation 接口保留,供 API 使用者选择更严格的流程。
- 不发送 `captcha_token` 的客户端在开启后一律失败,没有任何绕过;`/api/v1/tokens`(邮箱密码换令牌)不受人机验证保护,PicGo 等无交互上传不受影响。

## SMTP 与邮箱验证码

在「系统设置 → 邮件」配置 SMTP,「测试发信」用已保存的设置发一封测试邮件(默认发给自己,每 IP 每分钟 3 次)。

| 项 | 说明 |
| --- | --- |
| 加密 | `tls`(465)/ `starttls`(587)/ `none`(25,仅限内网无认证中继) |
| 密码 | 只写不读,同样用主密钥加密;未配置主密钥时只能保存无认证中继 |
| 失败提示 | 只给 `connect` / `tls` / `auth` / `rejected` 四类原因和 SMTP 数字码,不回显服务器原文 |

开启「邮箱验证注册」后(需 SMTP 可用):

- 注册必须带邮箱收到的 6 位验证码;人机验证(若开启)移到发送验证码那一步。
- 验证码 10 分钟有效,60 秒内不能重发,错 5 次作废,用掉即删;每个(用途,邮箱)只保留最新一条。
- 发信失败会作废本次验证码,不会留下一个收不到的码。

## 找回密码

用户操作：打开登录页 →「忘记密码？」→ 输入注册邮箱 → 按需完成人机验证 →「发送验证码」→ 填邮箱收到的 6 位验证码和新密码 →「设置新密码」→ 返回登录。未看到入口时，请让管理员检查邮件是否启用。

接口对应：`POST /api/auth/email-code`(`purpose=reset_password`)发码,`POST /api/auth/password-reset` 用码重置(每 IP 每分钟 3 次)。

未注册、已停用的邮箱与冷却期内都返回同样的成功提示,**不泄漏账号是否存在**。重置成功后该账户的全部令牌被撤销——所有已登录设备和 PicGo 令牌都会失效,需要重新登录。

## 速率限制一览

| 动作 | 限制 |
| --- | --- |
| 登录 / 注册 / 发码接口 | 每 IP 每分钟 3 次 |
| 管理端邮件测试 | 每 IP 每分钟 3 次 |
| 验证码重发 | 60 秒冷却 |
| 验证码尝试 | 5 次错误作废 |
