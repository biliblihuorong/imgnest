# 随机图片链接

随机链接让一个地址每次访问都跳到相册内随机一张图的真实直链(`307` 重定向),常用于博客背景、README 头图、随机壁纸。

## 地址形态

```
https://img.example.com/random/{uid}/{token}
```

- `uid` 是所有者的 10 位随机公开 ID,`token` 是 24 位随机串,都由系统生成,无法猜测,也不泄漏账号信息。
- 在相册详情页开启「随机图片」即可得到地址;地址可以随时**停用**(保留 token,恢复即用)或**重置**(换新 token,旧地址立即失效)。

## 行为细节

| 场景 | 结果 |
| --- | --- |
| 默认 | 跳转到随机图片的 WebP 版;没有 WebP 时回退原图 |
| `?format=original` | 跳原图;缺原图时回退 WebP;其他取值返回 400 |
| 相册里没有可用图片、链接停用、用户被禁用、地址格式错误 | 一律相同的 404,不区分原因,也不泄漏任何信息 |
| 访问过于频繁 | 每客户端地址每分钟 600 次,超限返回 429 |

- 参与随机的是相册内全部可用图片,**不看公开 / 私有**:创建链接就是所有者的显式授权,首次启用时界面会提示私有图片也会被匿名访问。回收站中的图片不参与。
- 响应带 `Cache-Control: no-store`,不会返回图片元数据与 EXIF。
- 重置 token、停用链接、禁用用户都会在下一个请求立即生效。

## 缓存与多实例

候选图片列表在服务端缓存 60 秒(每相册最多 5000 张,超出随机采样)。相册内容变化时缓存主动失效;多实例部署且未接共享缓存时,其他实例的失效最多延迟 60 秒——此时跳转目标本身已经是 404,不会泄漏已删除的内容。

## 配合外链使用

直链地址由存储的 `base_url` 拼出,换域名只需要在后台改存储的 `base_url`,随机链接本身不变。
