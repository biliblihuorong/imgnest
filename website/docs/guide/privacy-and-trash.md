# 隐私与回收站

照片里常带着拍摄地点、设备序列号这类信息。ImgNest 把完整信息留在你自己的数据库里，放到云端的文件则先清理掉敏感部分。

## EXIF 怎么处理

上传一张图时，按这个顺序处理：

1. 读出全部 EXIF 和 XMP，存进本地数据库。
2. 按规则的 `scrub_mode` 清理要放到存储里的原图。
3. 生成 WebP 和缩略图，这两个版本不带 EXIF 和 GPS，只保留 ICC 色彩配置。

清理是**无损**的：直接改写文件里的元数据部分，不解码也不重新编码像素，画质和你上传的文件完全一样。

## 清理档位

| `scrub_mode` | 清掉什么 | 保留什么 |
| --- | --- | --- |
| `gps`（默认） | GPS、作者与所有人、机身和镜头序列号、整个 XMP、厂商私有数据 | 相机型号、镜头、曝光参数、拍摄时间、方向、ICC |
| `all` | 全部 EXIF | 方向和 ICC |
| `none` | 不清理 | 全部 |

::: warning HEIC 和 AVIF
这两种格式暂时不支持原位清理。规则里可以选择只保存 WebP（默认）、原样保存不清理，或者拒绝上传。
:::

清理失败时上传会直接失败，不会把没清理的原图放上去。

## 谁能看到 EXIF

| 位置 | 能否看到 |
| --- | --- |
| 图片的主人、管理员 | 能看到完整 EXIF，包括 GPS |
| 公开画廊 | 看不到 |
| 蓝空 v1 接口 | 看不到 |
| 存储里的原图文件 | 按 `scrub_mode` 清理后的结果 |

GPS 坐标不会写进日志。

## 回收站

删除一张图不会马上把它抹掉：

1. **删除**：原图、WebP、缩略图一起移到存储里的回收区，原来的地址立刻返回 404。占用的容量马上从你的额度里扣除。
2. **保留**：默认保留 7 天。这期间在「回收站」里可以预览和恢复。
3. **恢复**：文件移回原来的位置，原链接恢复可用。回收站里的图片仍然占着原路径，不会被新上传的图抢走。
4. **到期**：定时任务每小时清理一次到期的图片，文件、缩略图和数据库记录一起删除。

回收站里也可以选中图片「彻底删除」，不用等到期。

::: tip 调整保留天数
在「站点管理 → 站点设置」里改回收站天数。设为 0 等于关闭回收站，删除就是直接删除。
:::

### 为什么不是只改数据库

S3 类存储的图片由存储桶的域名直接提供访问，不经过 ImgNest。如果删除只是在数据库里做个标记，文件还在原处，链接就一直打得开。所以删除时必须真的把文件移走。

### Backblaze B2

在 B2 上，不带版本号的删除只会加一个删除标记，旧版本还在，也还在计费。ImgNest 彻底删除时会列出这个文件的所有版本逐个删掉。建议同时给存储桶设一条「只保留最新版本」的生命周期规则作为兜底。

CDN 上的缓存不归 ImgNest 管，需要的话请在 CDN 一侧刷新。

## 上传失败时

一次上传要写入多个文件。任何一个文件写入失败，或者最后的数据库事务失败，这次上传已经写进去的文件会全部删掉，不会留下没有记录的孤立文件。

服务重启时，会先把上次没做完的上传、删除、恢复处理完，再开始接收请求。
